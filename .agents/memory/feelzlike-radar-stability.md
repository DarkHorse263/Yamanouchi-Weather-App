---
name: feelzlike radar stability
description: Why the feelzlike town-weather radar must stay in-repo and lead with the Interactive view, not a third-party iframe.
---

The radar must be self-hosted in the feelzlike monorepo. Do not reintroduce a primary radar that is an iframe to another Replit project or any single third-party SPA.

**Why:** A previous design embedded `global-snow-radar.replit.app` as an iframe with a 12s timeout fallback to the in-repo `RadarMap`. It broke repeatedly because (a) cross-origin iframes can't be introspected, so "iframe loaded but tiles inside are broken" never trips the fallback, and (b) the external dyno had its own sleep / regression / tile-provider failures that we couldn't see or fix. Users saw a black void with floating storm markers.

**How to apply:**
- Town weather page (`TownWeather.tsx`) must render `<RadarMap>` directly, never a wrapper that iframes another Replit deploy.
- `RadarMap.inner.tsx` defaults to the `interactive` view in both seasons. It was rebuilt to natively mirror the user's separate "Ski Radar" app: dark basemap (Esri WorldHillshade base + CARTO `dark_all` @0.86 on top), a "weather layers" panel with Precip Radar (RainViewer animated tiles, ON by default) plus four click-to-read point layers (Snowfall 24h / Wind Speed / Temperature / Rain Risk, OFF by default) that fetch Open-Meteo for the clicked lat/lng into a dark Leaflet popup. A METRIC toggle drives units. The old Overall/Clouds/Precip modes, satellite, and OpenSnowMap pistes/terrain were removed in this rebuild. Each layer still renders independently so any single upstream failure (RainViewer/Open-Meteo) degrades gracefully instead of nuking the map.
- `OfficialView` (BOM/JMA tab) must keep its `onError` → "open source" link-out fallback, and must be keyed on the source URL so switching regions resets the failure state.
- If a request comes in to add a "richer" external radar, fold its functionality into `RadarMap.inner.tsx` (or stand up a sub-artifact in this monorepo) — do not iframe a separate Replit project.

**Animated precip must NOT remount per frame.** Render every RainViewer frame as its own persistent `<TileLayer>` keyed by that frame's own stable timestamp, and animate purely via the `opacity` prop (active frame ~0.85/0.65, all others 0). react-leaflet updates opacity in place (`setOpacity`, no remount) and hidden layers still preload tiles, so stepping is an instant opacity flip.

**Why:** the bug was a single `<TileLayer key={\`rad-${currentRadar.time}\`}>` whose key changed every frame, forcing React to unmount/remount the Leaflet layer each step. A freshly mounted GridLayer starts blank and refetches all tiles, so every frame flashed a gap before tiles arrived — in every region (structural, not data). Do not reintroduce a frame-keyed single radar layer.

**How to apply:** frames are bounded to a **circular** sliding window around the current frame (not all ~16 mounted), still keyed by each frame's own timestamp and animated by opacity — never a single frame-keyed layer. The window MUST be circular (ring distance, not linear) because playback wraps last→0; a linear window leaves frame 0 unmounted at wrap and flashes. The bound was added after the cross-region "all of <country>" zoom-out surfaced a latent mobile failure: every mounted frame refetches its tiles on each zoom, so ~16 layers blanked the map on a big zoom-out/in. Pinch tile thrash is further reduced with `updateWhenZooming={false}`. If mobile still strains, shrink the window; do NOT revert to a single keyed layer (reintroduces remount-flash).

**Radar tile resolution (verified empirically AU + JP, Jun 2026).** RainViewer's mosaic carries real radar tiles through **z7** and serves a uniform placeholder PNG at **z8+** (byte signature at `/256/`: a covered-but-dry tile ≈334B, the no-data placeholder ≈1370B, a tile with precip 5–46KB; `/512/` runs ~3x those). So the precip `<TileLayer>` uses `maxNativeZoom={7}` — never 8, which swaps real precip for blank placeholders — and Leaflet CSS-upscales z7 for the deeper town zoom. To kill "pixelated radar on mobile", radar tiles are fetched at `/512/` on high-DPI screens (`devicePixelRatio > 1`) and `/256/` on 1x; the 512 source is downsampled into the default 256 CSS-px slot (`RADAR_TILE_PX` in `RadarMap.inner.tsx`). The dark basemap is already retina via Leaflet's `{r}` token; only the RainViewer layer (its URL has no `{r}`) needed the manual size pick. Do NOT raise maxNativeZoom past 7 or revert to always-`/256/`.

**Only `RadarMap.inner` is user-reachable; the region-router `Radar` (e.g. Yamanouchi `MapView` in `pages/map.tsx`) is dead.** `RegionLayout`'s `/radar` route redirects to `/:defaultTown/weather` whenever a base town exists, and every active region defines `baseTowns`, so `routes.Radar` never renders. `TownWeather.tsx` embeds `<RadarMap>` for ALL regions (AU + JP). When asked to "fix the radar," edit `RadarMap.inner.tsx`; do NOT edit `MapView`/`pages/map.tsx` (it only looks like the radar).

**The Interactive radar has no free corner — do not add a Leaflet zoom control.** Top-left = view switcher (Interactive/Expert/Official `TabPill`s), top-right = weather-layers panel/chip, bottom = full-width timeline overlay (z-1000) + required OSM/CARTO/Esri attribution. The default `zoomControl` sat occluded under the top-left switcher, so it's set to `zoomControl={false}`. Zoom still works via `scrollWheelZoom` (desktop), pinch, and double-tap. On mobile the `TabPill` labels collapse to icon-only (`sr-only sm:not-sr-only` + `title`) so the switcher and layers chip don't collide.
**Why:** repeated mobile crowding ("Official" truncated, controls overlapping). **How to apply:** keep controls icon-compact on phones; never reintroduce a `<ZoomControl>` expecting a spare corner.
